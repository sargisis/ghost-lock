# ghost-lock

**Аудит и укрепление iPhone поверх Lockdown Mode.** Локальный тулкит на Python + Go:
форензика краш-логов против шпионского ПО класса Pegasus/Predator, авто-аудит при
подключении по USB, профили жёсткой защиты на телефон и алерты в Telegram.

Без джейлбрейка. Без Apple Developer аккаунта. Без сторонних приложений на телефоне.
Всё работает локально.

---

## Как это устроено

iOS закрыта: без джейлбрейка в телефон нельзя поставить фонового демона или
дописать что-то внутрь Lockdown Mode. Поэтому ghost-lock построен на легальных
механизмах и закрывает **четыре независимых слоя**:

| Слой | Где | Что даёт |
|---|---|---|
| **Lockdown Mode** | Телефон | Базовый слой Apple — ghost-lock его не трогает, а дополняет |
| **Профили** (`dns_shield`, `hardened`, `web_filter`) | Телефон, постоянно | Зашифрованный DNS, системные ограничения, блоклист шпионских доменов на уровне WebKit |
| **Аудит** (`audit`) | ПК, по кабелю | Форензика: скан выгруженных краш-логов, приложений, гигиены; история и diff между проверками |
| **Автоматизация** (`glock-watch`) | ПК, постоянно | Сам видит подключение айфона → сам запускает аудит → сам шлёт вердикт в Telegram |

Философия: **Lockdown Mode предотвращает, ghost-lock детектит и верифицирует.**

## Быстрый старт

> **Linux · macOS · Windows:** полная инструкция по установке на каждую
> платформу — [docs/INSTALL.ru.md](docs/INSTALL.ru.md) (EN:
> [docs/INSTALL.md](docs/INSTALL.md)). Демон авто-аудита работает только
> на Linux; всё остальное кроссплатформенно.

```bash
sudo apt install libimobiledevice-utils   # если ещё нет
python3 ghost_lock/ghost_lock.py doctor   # проверка окружения
python3 ghost_lock/ghost_lock.py devices  # список айфонов
python3 ghost_lock/ghost_lock.py audit    # полный аудит + HTML-отчёт
```

При первом подключении разблокируй айфон и подтверди «Доверять этому компьютеру».
Отчёты складываются в `~/.local/share/ghost-lock/reports/`.


## Аудит: что происходит внутри

1. **Выгрузка краш-логов** — основной источник следов: в логах падений остаются
   упоминания C2-доменов, имён имплантов, джейлбрейк-артефактов.
2. **IOC-скан** гибридным движком: тяжёлая часть в Go (воркер-пул), эвристики
   URL/фишинга в Python. Allowlist отсекает ложные срабатывания (например,
   легитимный `Pegasus.framework` из состава iOS).
3. **Скан приложений** против известных bundle-id стalkerware
   (mSpy/FlexiSPY/CocoSpy/uMobix/EyeZy…).
   **Установленные конфигурационные профили** читаются по кабелю за секунды
   (нужен `pymobiledevice3`, см. ниже): всё не от ghost-lock помечается в
   каждом аудите, а не только в deep. Только имена — что внутри чужого
   профиля (MDM, сертификат, VPN), покажет `audit --deep`.
4. **Гигиена безопасности**: что читается по кабелю (активация, состояние пароля),
   с честными пометками «не читается» там, где iOS не отдаёт данные.
5. **Свежесть iOS** через api.ipsw.me — устаревшая версия = рабочие известные
   эксплойты.
6. **Diff «что изменилось»**: новые/удалённые приложения, незнакомые краш-логи —
   сравнение со всей историей предыдущих аудитов (SQLite).

Скоринг: `<3` чисто · `3–14` подозрительно · `≥15` критично.

### Глубокий режим

```bash
python3 ghost_lock/ghost_lock.py audit --deep
```

Полный бэкап телефона через `idevicebackup2` (SMS-базы, история Safari,
сетевая статистика) + скан всего содержимого. Первый прогон — десятки минут,
дальше инкрементально быстро. Обычный аудит смотрит сотни файлов, deep — десятки тысяч.

**Зашифрованные бэкапы.** Профиль `hardened` включает `forceEncryptedBackup`,
поэтому после его установки телефон отдаёт только шифротекст. ghost-lock *до*
бэкапа спрашивает у телефона, будет ли он зашифрован, берёт пароль бэкапа из
`GHOST_LOCK_BACKUP_PASSWORD` или с клавиатуры, расшифровывает во временную
папку (`pip install cryptography`), сканирует и сразу удаляет открытую копию.
Нет пароля или он неверный → аудит помечается **НЕПОЛНЫМ** в консоли, отчёте и
Telegram — скан шифротекста никогда не выдаётся за «чисто». Незашифрованный
бэкап даёт предупреждение: он лежит на диске открыто; включи шифрование:
`idevicebackup2 -i -u <UDID> encryption on`.


### shutdown.log (sysdiagnose)

При каждой перезагрузке iOS записывает процессы, которые мешали выключению.
Исследование Kaspersky «iShutdown» (2024) показало: импланты Pegasus, Reign и
Predator висели там из нестандартных мест (`/private/var/db/`,
`/private/var/tmp/`), а журнал переживает удаление импланта и хранит историю
многих перезагрузок. ghost-lock читает только `shutdown.log` из самого свежего
`sysdiagnose_*.tar.gz`, в памяти, и помечает такие пути, а также имена
процессов и пути из базы IOC.

Сними sysdiagnose на телефоне (обе кнопки громкости + боковая на 1–1,5 с,
короткая вибрация; собирается ~10 минут). Следующий `audit` его подхватит —
или забери и проверь сразу по кабелю:

```bash
python3 ghost_lock/ghost_lock.py sysdiagnose
```

### Сетевая активность процессов (deep-режим)

iOS записывает в `DataUsage.sqlite` каждый процесс, выходивший в сеть; имя
импланта остаётся там даже после удаления бинарника. Имя процесса — отдельное
поле, поэтому сверяется с секцией `processes` базы IOC **точно** (не
подстрокой — именно поэтому для краш-логов эта секция выключена). Имена,
совпадающие с настоящими демонами Apple (`roleaccountd`, `updaterd`), выводятся
с низким весом для ручной проверки; пути процессов сверяются с `file_paths`.
Записи трафика, ссылающиеся на удалённый процесс (след подчистки, который ищет
MVT), считаются и показываются как информация, пока не набрана норма для
чистого телефона.

### Аудит профилей и сертификатов (deep-режим)

Сталкерware и «корпоративная» слежка часто приходят **конфигурационным
профилем**, а не приложением. Пока расшифрованный бэкап на месте, deep-режим
проверяет:

- **Чужие профили** с весом по силе: MDM (15), корневой сертификат или
  глобальный прокси (10), VPN (8), чужой DNS или веб-фильтр (7), плюс префиксы
  `stalkerware_profiles` из базы IOC. Профиль считается «своим» только если
  совпадает и *содержимое* (тип payload, DoH-сервер из наших пресетов): имя
  `cc.ghostlock.*` подделать легко.
- **Пользовательские доверенные сертификаты** в `TrustStore.sqlite3` (риск MITM).
- **Супервизию** (`CloudConfigurationDetails.plist`).
- **Собственное покрытие**: какие профили ghost-lock стоят, совпадает ли список
  Domain Wall с текущей базой IOC и сколько ограничений `hardened` iOS
  реально применила (`EffectiveUserSettings.plist`).

Нужен зашифрованный бэкап: в незашифрованном файлы лежат под хешами.

## История аудитов и diff

Каждый аудит сохраняется в `~/.local/share/ghost-lock/history.db`.
Следующая проверка показывает дельту:

```
[*] Что изменилось с прошлого раза…
  🆕 Новые приложения (1): com.evil.stalker
  📉 Новых краш-логов: 14
```

Сталкер проще всего поймать именно по изменениям, а не по абсолюту.
Три строки diff уезжают в Telegram-алерт.

## Профили на телефон

```bash
python3 ghost_lock/ghost_lock.py profiles --usb     # по кабелю (рекомендуется)
python3 ghost_lock/ghost_lock.py profiles --serve   # раздать по Wi-Fi
# или просто отправить файлы из ghost_lock/profiles/ себе в мессенджер
```

**По кабелю** (`--usb`) сеть не нужна: раздача по Wi-Fi часто молча не
работает — файрвол ПК отбрасывает входящие соединения или роутер изолирует
Wi-Fi-клиентов. Используется `pymobiledevice3` в отдельном окружении (системный
pip в Debian/Ubuntu запрещён, PEP 668):

```bash
python3 -m venv ~/.local/share/ghost-lock/venv
~/.local/share/ghost-lock/venv/bin/pip install pymobiledevice3
```

Профили отправляются по одному — каждый подтверди на телефоне (Установить →
код-пароль). `--hardened` добавляет профиль ограничений. Проверено на iOS 27:
`profile store` для DNS-профиля телефон отклоняет («not permitted», ошибка
4022), а `profile install` показывает обычный запрос установки — его ghost-lock
и использует.

На телефоне: открыть файл → Установить. Проверка: Настройки → Основное →
VPN и управление устройством. iOS покажет «Профиль не подписан» — нормально
для ручной установки.

> Установка новых профилей требует временно выключить Lockdown Mode
> (Настройки → Конфиденциальность и безопасность). После установки включи обратно.

| Файл | Тип payload | Что делает |
|---|---|---|
| `dns_shield.mobileconfig` | DNS Settings (DoH) | Зашифрованный DNS + фильтрация на уровне резолвера. IP DoH-сервера зашиты в профиль (`ServerAddresses`), фолбэка на открытый DNS нет (`AllowFailover=false`) |
| `web_filter.mobileconfig` | Web Content Filter | **Spyware Domain Wall**: топ-500 C2-доменов Pegasus/Predator/FinFisher блокируются на уровне Safari/WebKit — второй эшелон, работающий даже мимо нашего DNS |
| `hardened.mobileconfig` | Restrictions | Системные ограничения поверх Lockdown Mode |

Пресеты DNS-щита:

| Пресет | Блокирует | Пример |
|---|---|---|
| `mullvad` *(default)* | малварь, реклама, трекеры (Mullvad Base, без логов) | — |
| `quad9` | малварь, фишинг (Quad9, без логов IP) | `profiles --preset quad9` |
| `family` | малварь, фишинг, взрослый контент (CleanBrowsing Family) | — |
| `cf-family` / `security` | варианты Cloudflare без контентной части | — |
| `nextdns --nextdns-id <ID>` | что настроишь в панели my.nextdns.io | `profiles --preset nextdns --nextdns-id abc123` |

**Фолбэка на открытый DNS нет — намеренно.** Иначе сеть, блокирующая DoH,
могла бы тихо перевести телефон на нешифрованный DNS; вместо этого в такой
сети телефон остаётся без DNS. Провайдеры и роутеры бывают, что режут
известные резолверы, поэтому перед установкой проверь каждую сеть, где
бывает телефон:

```bash
python3 ghost_lock/ghost_lock.py dns-check
```

Команда шлёт настоящий DoH-запрос прямо на зашитый IP каждого пресета (через
`curl`, он умеет и HTTP/2) с проверкой сертификата — ровно как сделает iOS.
Заодно проверяет ПК: `systemd-resolved` умеет только DoT (порт 853), поэтому в
такой сети он либо утекает на открытый DNS роутера, либо перестаёт отвечать.
Тогда `dns-check` выводит готовый конфиг `dnscrypt-proxy` с DoH на порту 443.

> **Файрволы с защитой от обхода DNS** (например, Portmaster) не пускают
> программы — включая `curl` и `dnscrypt-proxy` — к известным DNS-серверам и
> резолвят всё сами. `dns-check` предупреждает, если запущен Portmaster: его
> «блокировки» — это файрвол, а не сеть. С Portmaster зашифрованный DNS-сервер
> задаётся в нём самом (Secure DNS → DNS Servers), например
> `dot://base.dns.mullvad.net?ip=194.242.2.4&name=Mullvad`, а не
> вторым прокси. Именно DoT: запись Mullvad DoH Portmaster помечал как
> неработающую (DoH-сервер Mullvad говорит только по HTTP/2). И выключи в
> Portmaster откат на открытый DNS сети.

> Прежние версии писали ключ `ServerFallback`. У Apple такого ключа нет, iOS
> его игнорировала. Deep-аудит замечает установленный профиль этой версии —
> переустанови его.

Стена доменов пересобирается из актуальной базы IOC командой `profiles`
— переустанови файл, чтобы обновить список.

## Авто-аудит при подключении USB

Go-демон слушает kernel-события через netlink, видит подключение айфона и сам
запускает полный аудит. Ставится пользовательским systemd-сервисом:

```bash
./deploy/install_watch.sh
```

```bash
systemctl --user status glock-watch     # жив ли
journalctl --user -u glock-watch -f     # логи аудитов в реальном времени
```

Кулдаун 90 секунд защищает от повторных срабатываний. Чтобы сервис стартовал
до логина: `sudo loginctl enable-linger $USER`.

Одновременно идёт только один аудит (файл-замок), а демон вызывает
`audit --if-stale 15`: во время deep-бэкапа телефон переподключается по USB,
и без порога это запускало бы второй аудит и дублирующий алерт в Telegram.
После обновления перезапусти `./deploy/install_watch.sh`.

## Telegram-алерты

```bash
python3 ghost_lock/ghost_lock.py setup-telegram --token <ТОКЕН_ОТ_BotFather>
```

Скрипт сам поймает chat_id (напиши боту любое слово во время настройки) и вышлет
тестовое сообщение. Дальше каждый аудит — включая автоматические — присылает
вердикт, score и топ находок. Токен лежит в `~/.config/ghost-lock/telegram.json`
с правами 600, вне репозитория. Нет сети или конфига — аудит молча продолжается.

## База IOC

```bash
python3 ghost_lock/ghost_lock.py update-ioc
```

Парсер STIX 2.x тянет **все расследования AmnestyTech** (Pegasus, Predator,
FinFisher, DoNOT, NovaSpy, Wintego…) через GitHub API: домены, email'ы,
пути файлов. Имена процессов из кроссплатформенных отчётов сознательно
исключены из скана — они дают шквал ложных срабатываний в краш-логах iOS
(проверено: `roleaccountd`, `updaterd` — легитимные демоны Apple).

Текущий размер базы: **~4300 индикаторов**. Формат записи:
`{"value": "домен", "weight": 1-10, "source": "отчёт"}`.

## Честно об ограничениях

- Ключ `PasswordProtected` из lockdownd **ненадёжен на современных iOS**
  (проверено на iOS 27: показывает `false` при включённом пароле и Face ID).
  Гигиена трактует его как «неизвестно», никогда как «выключен». Настоящий
  статус код-пароля доступен только через MDM-супервизию — проверяй вручную.
- Обычный аудит видит краш-логи и метаданные, но не содержимое телефона;
  для полной глубины есть `--deep`.
- DoH-щит не видит трафик мимо DNS (заашитые IP); стена WebKit не контролирует
  нативный (не-WebKit) трафик. Именно поэтому слоёв несколько.
- Глубокая инспекция трафика внутри iOS требует своего NetworkExtension-VPN
  и Apple Developer аккаунта — вне scope проекта.
- Часть ключей hardened-профиля применяется только на устройствах «Под контролем»
  (Apple Configurator) — такие ключи помечены и честно игнорируются iOS.
- Установку профилей нельзя автоматизировать удалённо: Apple принципиально
  требует ручного подтверждения. Это же защищает профили от снятия зловредом.
